Built with

Data platform

Databricks Free Edition with a SQL warehouse. Python and SQL, with clean tables built from the raw files.

Models

Databricks-hosted Llama 3.3 70B by default, so there are no API costs. Claude can be used instead through one setting.

Application

FastAPI and a lightweight front end. DuckDB runs the same tables on a laptop for local testing. Tests run with pytest.

Design principles

Only a single read-only SELECT or WITH query can run. Anything else is blocked, and the block is covered by tests.

Every answer shows the SQL and the rows it came from, so each figure can be checked.

The dashboard and the agents read the same clean tables, so a chart and an answer always agree.

The agent team

Planner

Splits the question into one to three plain-English sub-questions. It never writes SQL.

Analyst

Writes one SQL query per sub-question and runs it on the clean tables.

Reviewer

Checks the SQL against the data rules and sends it back once if it is wrong.

Writer

Turns the approved results into a short answer for a non-technical client.

Data rules the agents follow

Revenue always means the sum of total_amount_usd on orders. Amounts are in US dollars.

Relative periods such as "last 12 months" count back from the latest order date in the data, not from today.

The data is sample data, not real customers. Tenure and signup-cohort questions are not answered because most orders predate the customer's registration date.
